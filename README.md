# CyberShield AI: AI-Powered Cyber Threat Detection (academic prototype)

A Flask + MongoDB web app that uses a Random Forest model to classify activity as **Normal** or **Attack**,
names the likely threat, calculates a risk score, raises alerts, and shows everything on a live dashboard.

> **Defensive and educational use only.** The model is trained on a **synthetic demonstration dataset**.
> Its ~99% test accuracy shows the pipeline works. It does **not** mean it will catch real-world attacks.
> Risk thresholds (0-30 Low, 31-70 Medium, 71-100 High) are **prototype values**, not a security standard.

## 1. Setup (Windows commands shown; macOS/Linux in brackets)

```bash
# 1. Install Python 3.10+ and MongoDB Community Server (must be running on localhost:27017)
python --version                       # [python3 --version]

# 2. In the project folder, create and activate a virtual environment
python -m venv venv
venv\Scripts\activate                  # [source venv/bin/activate]

# 3. Install packages
pip install -r requirements.txt

# 4. Create your private settings file
copy .env.example .env                 # [cp .env.example .env]
```
Open `.env` and set a real `SECRET_KEY` (generate: `python -c "import secrets; print(secrets.token_hex(32))"`)
and your own `ADMIN_PASSWORD`. **Never commit `.env`.**

```bash
# 5. Build the dataset and train the model (creates the .pkl files)
python dataset/generate_dataset.py
python model/train_model.py

# 6. Optional: automated test (uses a separate database, cybershield_test)
python tests/smoke_test.py

# 7. Run the app
python app.py
```
Open **http://127.0.0.1:5000** and sign in with `ADMIN_USERNAME` / `ADMIN_PASSWORD` from your `.env`.

**Expected output of step 7:** ` * Running on http://127.0.0.1:5000`

## 3. Dataset (`dataset/cybersecurity_data.csv`)

**Demonstration dataset**: 6,000 rows generated by `generate_dataset.py` from hand-written statistical profiles
of each traffic type, with ~1.5% label noise and ~1% missing values added on purpose so the cleaning steps are real.

| Feature | Meaning |
|---|---|
| `duration` | Connection length in seconds |
| `protocol` | tcp / udp / icmp |
| `service` | http / dns / ssh / ftp / smtp |
| `src_bytes`, `dst_bytes` | Bytes sent by the source / destination |
| `packet_count` | Packets in the connection |
| `connection_count` | Connections from the same source in a short window |
| `failed_logins` | Failed login attempts |
| `logged_in` | 1 if login succeeded, else 0 |
| `error_rate` | Share of connections that ended in errors (0 to 1) |
| `attack_type` | **Target**: Normal, Brute Force, DoS, Port Scan, Data Exfiltration |
| `label` | Simplified target: Normal or Attack |

`source_ip` and `destination_ip` are accepted in the UI and saved in alerts but are **not** model features.

### Using a real dataset (UNSW-NB15 / CICIDS2017)
Download it, map its columns to the table above (or edit `NUMERIC_FEATURES`, `PROTOCOLS`, `SERVICES` in
`utils/preprocessing.py` and the form in `prediction.html`), save as `dataset/cybersecurity_data.csv` with an
`attack_type` column, then re-run `python model/train_model.py`.

## 4. How the model is trained (`model/train_model.py`)
1. **Load** the CSV. 2. **Clean**: drop duplicates and unlabeled rows, normalise text, remove negative values.
3. **Missing values**: numbers get the column median, categories get the most common value (medians are saved
in `preprocessing.pkl` for use at prediction time). 4. **Encode**: one-hot encoding of protocol and service.
5. **Features**: 16 columns in a fixed order defined in `utils/preprocessing.py`. 6. **Split**: 80/20, stratified.
7. **Train**: Random Forest, 200 trees, balanced class weights. 8. **Evaluate**: accuracy, precision, recall,
F1, confusion matrix, 5-fold cross-validation. 9. **Save** with Joblib.

Typical result on the demo data (yours may differ slightly by library version): accuracy ~0.99,
Normal-vs-Attack recall ~0.99. Random Forests need no feature scaling, so no scaler is saved.

**Risk score** = 100 x sum(probability of each class x severity of that class), with prototype severities
Normal 0, Port Scan 0.55, Brute Force 0.90, Data Exfiltration 0.95, DoS 1.00 (`utils/risk_score.py`).

## 6. Security measures implemented
Passwords hashed (Werkzeug); secrets only in `.env`; HttpOnly + SameSite cookies, 2-hour sessions;
login rate limiting (5 failures / 5 min / IP); same error message for unknown user and wrong password;
strict server-side validation with whitelisted fields and ranges; IP addresses parsed with `ipaddress`;
output escaped in the browser (XSS); request size limit; security headers incl. Content-Security-Policy;
internal errors never shown to users. For real deployment you would also add HTTPS (`SESSION_COOKIE_SECURE=true`),
CSRF tokens, and persistent rate limiting.

## 9. Troubleshooting

| Problem | Fix |
|---|---|
| `Cannot start: ... ServerSelectionTimeoutError` | MongoDB is not running. Start the MongoDB service. |
| `SECRET_KEY is missing` | Create `.env` from `.env.example`. |
| `Model files not found` | Run `python dataset/generate_dataset.py` then `python model/train_model.py`. |
| Charts empty / not loading | Chart.js loads from the internet (cdnjs). Check your connection. |
| `ModuleNotFoundError` | Activate the venv, then `pip install -r requirements.txt`. |
| Port 5000 in use | Change `port=5000` at the bottom of `app.py`. |
| Locked out of login | Wait 5 minutes (rate limit) or restart the app. |
| Loading `.pkl` warns about version | Retrain with `python model/train_model.py` on your machine. |

## 10. Limitations (state these honestly)
Synthetic data; detection depends on the training data and cannot cover every real attack; analysts enter
activity manually (no live packet capture); prototype risk thresholds; single admin user; basic security
suitable for a college demo, not production.
